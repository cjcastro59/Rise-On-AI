## 1. Overview

Phase 3.2 evaluates three models on the **same held-out test set** (never seen
during training):

| Stage | Model | Purpose |
|-------|-------|---------|
| Keyword Baseline | Pure rule/keyword matching (no ML) | Establishes a non-ML floor |
| XLM-R Base | `FacebookAI/xlm-roberta-base` with a randomly initialised 3-class head | Shows what the pre-trained backbone achieves without fine-tuning |
| XLM-R Fine-tuned | Our trained model from `outputs/best_model/` | The actual production model |

Metrics computed for each:

- **Overall**: Accuracy
- **Macro average**: Precision, Recall, F1 (treats every class equally)
- **Weighted average**: Precision, Recall, F1 (weighted by class support)
- **Per-class**: Precision, Recall, F1, Support — for Positive / Negative / Distress
- **Confusion Matrix**: 3×3 (actual vs predicted)

## 3. Environment Setup

All commands below are run from inside
`scripts/sentiment-model-training/` unless stated otherwise.

```powershell
# 1. Navigate to the training directory
cd scripts/sentiment-model-training

# 2. Create and activate a dedicated virtual environment
python -m venv .venv-training
.venv-training\Scripts\Activate.ps1        # Windows PowerShell

# 3. Upgrade pip
python -m pip install --upgrade pip

# 4. Install all dependencies
pip install -r requirements.txt
```

> **GPU (CUDA) users**: replace the `torch` line in `requirements.txt`
> with the appropriate CUDA wheel before running `pip install`:
>
> ```powershell
> # CUDA 12.1
> pip install torch==2.3.1+cu121 --extra-index-url https://download.pytorch.org/whl/cu121
> pip install -r requirements.txt
> ```

## 4. What You Need Before Evaluating

You need **two things** before running evaluation:

### 4a. `data/test.csv`

Generated automatically by `01_prepare_dataset.py`.
If it does not exist yet:

```powershell
# Using synthetic Taglish data (demo / development)
python 01_prepare_dataset.py --synthetic-per-class 300

# Using your own labelled dataset
python 01_prepare_dataset.py --input path/to/your_labelled_data.csv
```

Expected columns: `text`, `label` (values: `positive`, `negative`, `distress`).

### 4b. `outputs/best_model/`

Generated by `02_finetune_xlmroberta.py`.
If the fine-tuned model does not exist yet, run fine-tuning first (see
Section 5) or place a pre-trained checkpoint in `outputs/best_model/`.

To verify both exist:

```powershell
# Should print the CSV row count
(Get-Content data\test.csv | Measure-Object -Line).Lines

# Should list model.safetensors (or pytorch_model.bin) + config.json
Get-ChildItem outputs\best_model\
```

## 5. Running the Full Pipeline

`run_pipeline.py` runs all four steps in order:
`01_prepare_dataset` → `02_finetune_xlmroberta` → `03_export_model` → `04_evaluate_model`

```powershell
# Quickest end-to-end run (synthetic data, 1 HP trial, 4 epochs)
python run_pipeline.py --synthetic-per-class 300 --trials 1 --epochs 4

# Production run (synthetic data, 8 HP trials, 8 epochs)
python run_pipeline.py --synthetic-per-class 500 --trials 8 --epochs 8

# Using your real labelled dataset
python run_pipeline.py --input path/to/dataset.csv --trials 8 --epochs 8

# Skip the base-model download during evaluation (faster, no internet after training)
python run_pipeline.py --synthetic-per-class 300 --trials 1 --skip-eval-base

# Skip ALL baselines — only evaluate the fine-tuned model
python run_pipeline.py --synthetic-per-class 300 --trials 1 --skip-eval-keyword --skip-eval-base
```

Phase 3.2 evaluation runs **automatically** as the final step.

## 7. Running the Standalone Evaluator

`05_evaluate_standalone.py` is a **self-contained** script.
It does not depend on any other pipeline script and can be run independently
on any machine that has the model weights and a labelled CSV.

```powershell
# Default: uses outputs/best_model/ and data/test.csv
python 05_evaluate_standalone.py

# Custom paths
python 05_evaluate_standalone.py --model outputs/best_model --test data/test.csv

# Evaluate on a completely different dataset (e.g. real user entries)
python 05_evaluate_standalone.py --test path/to/real_user_data.csv

# Skip base model (no internet / faster)
python 05_evaluate_standalone.py --skip-base

# All options
python 05_evaluate_standalone.py --help
```

Input CSV format for `--test`:

```csv
text,label
"I feel so happy today","positive"
"Nalungkot ako ngayon","negative"
"Ayaw ko nang mabuhay","distress"
```

Accepted label values: `positive`, `negative`, `distress`
(also accepts aliases: `pos`/`neg`/`dst`, `0`/`1`/`2`, `masaya`/`malungkot`/`crisis`)

Outputs land in `outputs/05_*` (never overwrites `outputs/04_*`).

## 9. Interpreting the Results

### What "good" looks like

| Metric | Acceptable | Target |
|--------|-----------|--------|
| Accuracy | ≥ 0.80 | ≥ 0.88 |
| F1 Macro | ≥ 0.75 | ≥ 0.85 |
| F1 Weighted | ≥ 0.78 | ≥ 0.88 |
| Distress Recall | ≥ 0.80 | ≥ 0.90 |

> **Distress Recall is the most critical metric.** A missed distress case
> means a user in crisis is not flagged. Prefer false-positives over
> false-negatives for this class.

### Reading the confusion matrix

Rows = actual class, Columns = predicted class.
Diagonal cells (top-left to bottom-right) = correct predictions.
Off-diagonal cells = errors.

```
              Predicted
              Pos   Neg   Dst
Actual  Pos  [ 45    3     2 ]   ← 3+2 = 5 errors on Positive
        Neg  [  4   40     6 ]   ← 4+6 = 10 errors on Negative
        Dst  [  1    5    44 ]   ← 1+5 = 6 errors on Distress
```

The most dangerous cell is row=Distress / col=Negative (bottom-middle):
those are real distress cases predicted as merely negative.

### Common misclassification causes

| Pattern | Likely cause | Suggested fix |
|---------|--------------|---------------|
| `negative` → `distress` | Strong hopeless phrasing without explicit crisis keywords | Add contrastive examples; increase distress class weight |
| `distress` → `negative` | Subtle distress cues not in training data | Collect more real distress entries; review ambiguous labels |
| `positive` → `negative` | Sarcasm, mixed-sentiment, or short text | Enforce minimum text length; add sarcasm examples |
| Any class with F1 < 0.70 | Insufficient labelled examples | Augment with back-translation or crowd-sourced annotation |

### Whether additional balancing is necessary

Check the `support_ratio_min_to_max` field in the JSON report:

- **≥ 0.5** → Acceptable. Current stratified split is sufficient.
- **< 0.5** → Imbalance detected. Apply: class weights in the loss
  function (already supported in `02_finetune_xlmroberta.py`), or
  upsample the minority class via `01_prepare_dataset.py --balance upsample`.

## 10. Troubleshooting

### `FileNotFoundError: data/test.csv`
Run `01_prepare_dataset.py` first (see Section 4a).

### `FileNotFoundError: outputs/best_model`
Run `02_finetune_xlmroberta.py` first (see Section 4b).

### `CUDA out of memory`
Reduce `--batch-size` in `02_finetune_xlmroberta.py`, or evaluate on CPU
(evaluation alone does not require a GPU).

### `ModuleNotFoundError: No module named 'peft'`
The venv is not activated or `pip install -r requirements.txt` did not complete.
Re-activate and re-install.

### `OSError: FacebookAI/xlm-roberta-base is not a local path`
The base model needs to download from HuggingFace on first run.
Ensure internet access, or use `--skip-base` to skip this comparison.

### Plots not rendering / empty PNG files
Ensure `matplotlib` and `seaborn` are installed.
The scripts use the `Agg` non-interactive backend — no display is required.

### Evaluation gives identical results to a previous run
This is expected and correct. Seed 42 is locked globally. Results will only
differ if `test.csv`, the model weights, or the script logic change.
